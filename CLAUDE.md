# stapel — правила для Claude Code в этом репозитории

## Что это

`stapel` ведёт тикет разработки от описания до слияния с повторяемым результатом. План — `docs/PLAN.md`,
фазы — `docs/PHASES.md`. Rust, одна рабочая область cargo.

## Как здесь работают

- На каждый критерий приёмки — тест, который сначала падает. Коммиты парами: RED (только тесты), затем
  GREEN (код). Один шаг плана — одна пара.
- Ревью перед слиянием: свежий ревьюер кода, внешний ревьюер, ревьюер расхождений. Ревьюеры работают на
  копии (`git archive`), без права записи в git и в рабочее дерево.
- Каждый вызов модели записывается в журнал токенов тикета с ролью и пометкой «замер» или «оценка».
- Агенты не делают `git push` и не меняют ветку в рабочем дереве. Пушит человек или оркестратор после
  ревью.
- В отслеживаемых файлах и сообщениях коммитов не должно быть приватных терминов (имя организации,
  фамилии). Авторство коммитов — `kyyyyf`.

## Язык

Документы, тикеты и сообщения человеку — по-русски, полными предложениями. Английские нарицательные в
русской грамматике не используем (объём работ, срок, задача, контрольная точка). Технические термины без
русского эквивалента — по-английски с пояснением при первом употреблении. Имена команд, файлов и моделей —
как есть. Идентификаторы в коде и сообщения коммитов — по-английски.

## Структура

```text
crates/stapel-core    тикеты, факты состояния, хеши разделов, проверки, журнал решений
crates/stapel-agent   провайдеры моделей, роли, пакеты контекста, журнал токенов
crates/stapel-index   индекс: адаптеры языков, радиус поражения
crates/stapel-forge   MR/PR, CI, комментарии к строкам
crates/stapel-mcp     MCP-сервер для агента
crates/stapel-lsp     LSP-сервер для Zed
crates/stapel-cli     бинарный файл `stapel`
docs/                 план, фазы, решения
.stapel/              процесс и тикеты этого репозитория
```
